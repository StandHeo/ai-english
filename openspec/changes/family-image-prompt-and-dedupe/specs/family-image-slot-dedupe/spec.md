## Purpose

减少家庭迷你关配图时因重复主体与抽象干扰词导致的重复 API 调用与劣质出图，通过规范化去重、同日跨关复用与干扰词治理提升稳定度与成本效率。

## ADDED Requirements

### Requirement: 槽位主体规范化去重
构建配图槽位时，系统 MUST 用规范化键判断主体是否重复。规范化 MUST 至少：去除首尾空白、转小写、剥除前导英文冠词（`a` / `an` / `the`），并以首个英文词为主键（多词主体取首词）。同一关内规范化键相同的主体 MUST 只保留一个道具槽。应用家长 `itemPrompts` 覆盖后，系统 MUST 再次按规范化键去重。

#### Scenario: a paper 与 paper 合并
- **WHEN** 某关选项 id 同时出现 `a paper` 与 `paper`
- **THEN** 配图槽位中对应主体只出现一次，不会为二者各请求一次文生图

#### Scenario: 覆盖主体后再去重
- **WHEN** 家长把两个道具槽的主体都改成同一规范化词（如均改为 `cake`）
- **THEN** 最终用于出图的槽位列表中该词只保留一处

### Requirement: 同日迷你 pack 跨关复用已生成图
在为同一日记日期的迷你 pack 批量云端配图时，若某关道具/干扰槽的规范化主体已在同日另一关成功生成过图像，系统 MUST 复用该图像，MUST NOT 再次调用画图 API（背景场景槽除外：每关场景仍按本关场景主体单独出图，除非规范化键与已缓存场景主体相同且产品选择复用——默认场景不跨关复用，仅道具/干扰复用）。

#### Scenario: 第二关重复主词不重复请求
- **WHEN** 第 1 关已为 `cake` 生成道具图，第 2 关干扰项也是 `cake`，家长对两关执行批量云端配图
- **THEN** 第 2 关该槽写入与第 1 关相同的图数据（或等价引用），且不产生第二次针对 `cake` 的文生图请求

#### Scenario: 各关场景仍独立
- **WHEN** 两关场景主题文案不同
- **THEN** 两关各自生成（或保留）背景图，不因道具复用规则被错误合并

### Requirement: 抽象与劣质干扰词不得作为配图主体
迷你 pack 生成与校验 MUST 拒绝将抽象/劣质词用作 picture option 的 `id`（至少包括表示纸张、形状、颜色类别的词，如 `paper`、`square`、`circle`、`color`、`shape` 及带冠词变体）。校验或清洗后，系统 MUST 尽量用具体童词名词替换，以保证 find/ask 选项仍有足够具体干扰项。

#### Scenario: 生成结果含 paper 时被清洗或拒绝
- **WHEN** 模型输出的某关 find 选项 id 为 `paper` 或 `a paper`
- **THEN** 该 id MUST NOT 原样进入最终可配图关卡；系统清洗替换为具体名词，或使该 pack 校验失败并触发既有重试/错误路径

#### Scenario: 具体干扰词可通过
- **WHEN** 干扰项 id 为具体可画童词（如 `bus`、`duck`、`tree`）
- **THEN** 校验通过，可作为配图道具槽主体
